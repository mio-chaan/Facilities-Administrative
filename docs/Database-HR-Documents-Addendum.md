# Database — HR Document Automation addendum

> Append this section to the existing `docs/Database.md` (or keep as
> a standalone note) — it documents the tables added by
> `database/migrations/2026_08_02_hr_document_automation.sql`, on top
> of the conventions already described in that file.

## New tables

| Table | Purpose |
|---|---|
| `team8_incident_reports` | Filed by an employee about themselves (session-trusted identity — see below). |
| `team8_notice_to_explain` | Generated by an admin FROM an incident report (`incident_report_id` FK). |
| `team8_explanations` | Submitted by the NTE's own employee in reply to a notice (`nte_id` FK). |
| `team8_memorandums` | Admin-authored memos; also backs **Warning Letters** via the `kind` column (`memorandum` \| `warning_letter`) — the task spec gave Warning Letter no distinct field set, so it reuses this table instead of a near-duplicate one. |
| `team8_certificates` | Admin-issued certificates (`certificate_type`: `employment` \| `recognition` \| `attendance`), issued to an employee chosen from the `users` directory. |
| `team8_hr_document_versions` | Shared, polymorphic version-history table (`doc_type` + `doc_id`) used by all four document types above. |

## Status model

All five HR tables use one shared status vocabulary instead of a
`deleted_at` soft-delete column: `draft → pending → approved` (or
`rejected`) `→ archived`. "Archived" **is** the soft-delete state for
these tables — there is no separate `deleted_at` here, unlike the
rest of the schema.

## No duplicated employee data

Every table stores only `employee_id` / `prepared_by` / `reviewed_by`
FKs into the shared `users` table (and `department_id` where
relevant). Names/departments are always resolved via `JOIN` at read
time in `app/includes/hr_documents.php`'s `t8_hr_*_fetch()` helpers —
never copied onto the row itself.

## Workflow

```
Incident Report → Notice To Explain → Employee Explanation → Admin Review → Archive
```

`team8_notice_to_explain.incident_report_id` and
`team8_explanations.nte_id` encode this chain; the UI (`modules/documents/hr/*.php`)
walks it in both directions (an incident report links forward to its
NTE, an NTE links forward to its explanation).

## Setup

```bash
mysql -u root -p capstone_shared_db < database/schema.sql
mysql -u root -p capstone_shared_db < database/migrations/2026_08_02_hr_document_automation.sql
```

Safe to run on a fresh clone or an existing local database — every
`CREATE TABLE`/`CREATE INDEX` is `IF NOT EXISTS`-guarded.
